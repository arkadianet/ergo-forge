# Play exports and share links

Play, exported scenarios and suites, and shared chains are **synthetic**.
Their sandbox verdicts do not establish node acceptance or a vulnerability.
The export documents carry `synthetic: true` and `nodeValidated: false`;
the existing CLI runners also label their results as scenario simulations.

## Export an input's evaluation

After running a Play transaction, each input has **Save as test** and
**Save as scenario** controls. Downloads are `contract.test.json` and
`scenario.json`. A refused transaction can still contain an input that passed;
the export records that input's verdict, not the transaction's overall outcome.

`POST /api/v1/play/export` accepts the same `height`, `network`, `boxes`,
and `tx` as `POST /api/v1/play`, plus a zero-based `inputIndex` and
`kind: "test" | "scenario"`. It returns the JSON document directly. It uses
Play's 1 MiB body limit, rate limiter and bounded engine thread pool.

The library entry point is `ergo_sandbox::play_export::export(request,
input_index, verdict)`. Its `PlayExport` holds a `Suite` (one `Case`) and a
`Scenario`. Both use the shared Play context constructor, including output
simulation IDs and default creation heights. Inputs and data inputs are
resolved by ID in transaction order; `selfIndex` chooses SELF. Context variables
belong to the selected input. The exact input ErgoTree is the suite contract;
cases omit tree/source because the suite runner supplies that contract. The
standalone scenario carries the tree directly. No source or params are exported.

Signing secrets and parties are omitted. When signing material was supplied,
the expectation comes from a fresh signature-less evaluation and the case name
records that change. Otherwise an export replay disagreement is refused with
`synthetic-drift`; it must be investigated as a shared-engine correctness bug.
No output IDs, scripts or expectations are patched to mask such a disagreement.

Run the downloaded documents unchanged:

```sh
ergo-es test contract.test.json --json
ergo-es eval scenario.json --json
```

## Share a chain or suite

**Copy Play share link** shares the current boxes (including spent flags),
height, network and optional history. History is the existing Play text log.
It does not include the inspector cache. **Copy suite share link** shares the
Tests area's current suite. Write's original **Copy share link** still carries
the source, params and network.

The `#s=` payload is UTF-8 JSON encoded as unpadded base64url:

- Write (unchanged): `{s: source, p: params, n: network}`; no `k` means Write.
- Play: `{k: "play", v: 1, height, network, boxes, history?}`.
- Suite: `{k: "suite", v: 1, suite}`.

New links generated by the UI also carry `synthetic: true` and
`nodeValidated: false`. Incoming experiment links never establish provenance;
the UI labels them synthetic. Unsupported kinds and versions are refused.

The fragment cap is **7168 bytes (7 KiB), including `#s=`**. It leaves roughly
1 KiB for an ordinary origin and path within an 8 KiB URL budget; unusually long
hosting paths may still exceed that budget. Both creation and loading report
the actual encoded size and the cap on refusal. Large suites should be shared
as files. There is no compression, CDN, server-side storage, validation route,
or network fetch involved in sharing. Rust gate tests execute `ui/share.js`
with Node so the browser and gate use the same codec.

Loading a Play link shows a **Replace my Play chain** / **Keep my chain**
choice. Only replacement writes the new chain to localStorage. Imported chains
render without automatic contract inspection requests. Loading a suite places
the full JSON in Write's Tests area; **Run tests** uses that document's own
contract. A scenarios array continues to use the active Read/Write contract.
Loading does not run a suite. Browser arithmetic must retain exact integer box
and token amounts; unsafe integer Play amounts are refused.
