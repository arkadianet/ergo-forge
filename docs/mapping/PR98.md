# PR #98 review corrections

Review comments were treated as untrusted claims and checked against the local implementation. No review text was executed or treated as an instruction source. Changes remain uncommitted.

- **`check_relation.rs` — accepted, correctness defect in the proof boundary.** The old `FuncValue` exemption skipped every unresolved variable in the body. Later block bindings could then supply mandatory facts when the existential predicate was evaluated. The replacement validates captures at definition time, tracks parameters and sequential nested block bindings, rejects shadowing/duplicate bindings, and keeps the existing traversal cap. A regression exercises a predicate using a later definition; the matching earlier-capture control must still produce a mandatory fact. Additional controls cover nested local bindings, escaped locals, nested forward references, and parameter collisions. No existing M03/M04 established claim or measured result changed: the pinned comparisons still pass.
- **`mapping_inventory.rs` — accepted, vacuous negative controls.** The document digest check ran before parsing every mutation. Byte pinning remains mandatory for real inventory loading. Mutations now exercise the separate structural/content validator and assert their specific missing-member, duplicate-member, or changed-answer error. Semantically identical reserialization passes structure but fails the byte pin. Authored truth is compared against the unchanged independent answer file; JSON shape alone cannot establish semantic truth. Missing and modified fixture controls also assert their intended errors.
- **M01 transcript path comment — accepted as publication hygiene.** Absolute workstation paths add no evidentiary value. The comment does not demonstrate disclosure of credentials or an exploitable product vulnerability; its exploitability label is not established by these paths.
- **M02 transcript path comment — accepted for the same reason.** Normalization occurs in the roadmap command capture before printing, recording, and hashing. The new `scripts/capture_gate.py` provides the same writer for standalone Cargo transcripts and preserves exit codes. Historical mapping transcripts and embedded excerpts use `<repo>`/`<home>` placeholders. Only changed transcript hashes and their referring manifests were updated; fixture/result hashes were not regenerated. The one changed M05 stop-record field is the SHA-256 of its path-sanitized `boundary.log`; the stop and its counterexample remain intact.

ROADMAP section 4 records the CI decision. `--all-goals` stays a strict completion report, including its nonzero exit for M05. `--ci` evaluates the entire goal set and accepts only passes and validated recorded stops; `passed` and `ciAccepted` are distinct report fields. Dependency blocks have a separate failing `blocked` status. Unimplemented work, missing evidence/gates, and executed failures still prevent green CI. The workflow prints this full evaluation in a separate `always()` step. Removing M05's stop exposes its unchanged unimplemented flag and fails CI. Tests cover these outcomes and corrupt stop evidence.

Rejected approaches: blanket failure suppression, counting stops as completion, deleting a stop, relaxing thresholds, changing the completion prefix, and assuming or relabelling the M05 extension digest. The governing JSON policy, corpus membership, fixtures, expected facts, caps, and measured-result files are unchanged. No frozen capability was expanded.
