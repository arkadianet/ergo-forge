# M03 — direct exact-tree necessity checker

Implemented on `mapping/m00-m05`, based on
`0545b16347a29dbe9b60bc1a3df46a5eb602bd8d`; left uncommitted for author review.
The author's request authorizes implementation after PR #97. M03 retains its

`mapping_necessity` target and all four registered test names. Only M03's
implementation flag and the completed prefix advance. M04–M05 remain unimplemented.

## Delivered boundary

`map::necessity::propose` produces untrusted, claim-bound structural derivation
candidates. Each anchor names the pinned parser's preorder node ID, opcode and
proposed rule. Separately callable `map::check_relation::check` rereads exact root
bytes, checks every anchor/rule, resolves lexical bindings and reconstructs
mandatory facts. Its `Established` capability has private fields and no
Deserialize implementation. Reports contain the complete proposal/P, premise and
claim digests, checked derivation and method. Importing a proposal or report never
establishes it: a fresh checker call is required. Discovery is not an input to the
checker, and legacy proposal status remains unresolved.

The checker reads `ergo_ser::opcode::{Expr, Payload, preorder}` from the unchanged
pinned node revision `9468043396e5daa2828211bcff4234bc70fae4f0` directly. No lift,
source reconstruction, recompilation certificate, new IR or evaluator is used.
The correspondence is to that revision's `ergo-sigma/src/evaluator/dispatch/eval.rs`
and its boolean, collection and box-context opcode handlers:

| Exact wire form | Checked inference |
|---|---|
| `BlockValue` / `ValDef` / `ValUse` | Scoped aliases; refuse ambiguous, forward or cyclic bindings |
| `BoolToSigmaProp` | Successful root requires its Boolean operand |
| lazy `BinAnd` | Union mandatory facts |
| lazy `BinOr`, `If` | Intersect common facts; select an `If` arm only from the recorded guard |
| positive `EQ` | Exact ID, proposition bytes/hash, literal token-position ID |
| ID `NEQ` to SELF | Explicit companion distinctness, tied to the same box binding |
| `Exists(INPUTS, FuncValue(Box))` | Literal identity at a distinct predicate scope; no data/output substitution |
| authenticated literal data-input ID plus typed `OptionGet(ExtractRegisterAs)` | One fixed canonical config register supplies exact bytes; no mutable invariant or register chain |

Selectors must use bounded canonical lowercase hex and positive token amounts;
noncanonical encodings are refused before comparing SELF or deriving facts.
Conjunction selectors require facts about the same box binding. Distinctness
requires an explicit ID inequality at that binding or fixed SELF failing the
selector. Token ID checks prove minimum amount 1 only under the recorded
positive-input-token state restriction; they prove neither uniqueness nor code.
Authentication field paths name exact input/data-input slots and fields, including
`inputs/1/id`, `inputs/1/proposition-bytes` and `inputs/1/proposition-hash`.

Unknown/negated/optional/defaulted expressions supply no mandatory facts. Unknown
branches contribute no facts common to all alternatives. This is deliberately
conservative: different witness bindings across alternatives, general token
membership searches, arbitrary fields/guards, computed indexing, AVL credentials,
register chains and extension execution are not promoted. Dependencies are refused
entirely for this direct fragment, so cycles cannot discharge their own premises.
The new analysis bounds are 65,536 root bytes and at most 10,000 nodes/traversal
visits; only the explicitly supported `nodes` cap key is accepted. Legacy caps
are unchanged.

The corrected section 3.1 relation binds A to fixed canonical SELF and exact root
bytes before checking. P carries one typed guard, pinned revisions and provenance,
authentication roots, and the full supplied validator state/configuration. A
script subject still has fixed SELF bytes; this is not a varying script family.
State restrictions exclude storage-rent eligibility for SELF and require positive
input token amounts. The checker verifies the age/activation boundary rather than
accepting a caller's assertion that the root or companion must execute. These
claims are conditional on supplied state; they do not cover all future heights.

## Independent evidence and results

The gate loads and hash-checks the unchanged M00 manifest, independent answers and
all 32 fixtures. All 12 M03-supported Spend positives establish. All 18 pinned
adversarial/unsupported members are refused; the two supported Execute claims are
explicitly deferred to M05, retained in the all-family results. The original
14-supported-claim denominator is preserved. There are zero incorrect established
relations among the 12 pinned establishments and 20/32 unresolved claims.

Five additional positive/control pairs check common alternatives, literal guards,
Boolean guard combinations, explicit distinctness when SELF matches a token
selector, and proposition-hash identity. They are separately reported: five
established and five refused, without changing the M00 denominator. Authentication
checks exercise exact ID, script bytes and script hash, with wrong field/bytes
controls. Mutation checks refuse missing/reordered/altered anchors or rules,
cycles, changed guard/revision/root/subject, exhausted caps, missing fixed config
and storage-rent-eligible state.

There are 53 full-node vectors derived from the pinned M03-relevant inputs plus
20 supplemental vectors: **73 executions, 52 accepted and 21 rejected with
`ProofFailed { index: 0 }` at `node-validation`**. Balance outputs are explicit
synthetic fixture material; the canonical spending input bytes are retained.
Every supported positive has an accepted satisfying transaction with a true guard,
a well-formed omission rejected at A's script and an accepted relaxed/alternative
control. The fixtures replay through the existing `evidence::validate::validate`,
not scenario reduction or a new validator.

The test independently assesses actual node-resolved spending inputs using the
same P, bound A, true guard and distinct companion predicate. **27 accepted
omissions refute their own exact claims**, including `literal_spend`,
`action_alternatives` and `exists_literal` controls. No accepted same-premise
omission contradicts an established claim. A vector at another height has its own
complete P and digest; it never refutes a claim by silently changing premises.
Data inputs and outputs are never counted as spending companions. The assessments
are test evidence, not M04's product action/witness-import/refutation API.

## Amendments and retained history

The [design amendment](../superpowers/specs/2026-09-10-comprehensive-mapping-design.md)
adds `HeightAtLeast(Int)` because the equality-only vocabulary could not express
the already pinned `HEIGHT >= 100` guard. It also spells out the conditional
state restrictions needed to exclude non-script acceptance. No pinned M00–M02
case, expected fact, numeric baseline, threshold or gate changed.

Review found that the new supplemental v1 document retained unused `truth`,
rationale and lexical-site annotations from its construction template. Supported
dispositions, selectors, guards and execution verdicts were correct; the gate
originally did not check the inherited truth field. Its
[original fixture](../../ergo-sandbox/tests/fixtures/mapping/m03/supplemental.fixture)
and [original result](m03-mapping-results-v1.json) are retained. Separately pinned
v2 records truth about each supplemental claim and removes inherited annotations;
the strengthened gate checks truth too. All ten member IDs, targets, guards,
supported dispositions, all 20 request bytes/hashes and expected execution verdicts
are identical across versions. This versioned supplemental metadata correction
preserves prior evidence and does not change the M00 denominator or weaken a gate.

Final review also aligned selector encoding checks: text-based SELF matching and
byte-based derivation now share a strict canonical-hex admission boundary. An
adversarial uppercase import is refused. No contradictory accepted/established
artifact was produced. All gates were rerun after this defensive fix.

Initial Clippy output reported unnecessary casts and redundant pattern matching;
those were fixed. Intermediate authoring/unit logs are retained separately from
final verification. No capability stop was needed. No new discharge integration,
drain/search axis, detector, action checker, request-generation product API,
extension resolver, UI or network/protocol access was added.
