# M00 — fixed mapping inventory

Implementation scope: M00 only, following the author-authorized design merged in
PR #97. No extractor, relation checker, action checker, production API, detector,
search axis, UI, or legacy behavior is added. Work is uncommitted for review.

The inventory is [manifest.json](../../ergo-sandbox/tests/fixtures/mapping/manifest.json),
with a separately authored [expected.json](../../ergo-sandbox/tests/fixtures/mapping/expected.json).
Its 16 named positive/control families contain 32 cases, 52 lexical reference
sites, 160 canonical hypothetical boxes (five per case, including unrelated
material), and 67 supplied reduction vectors. Names are case-local: identical
canonical material can recur across different cases. The manifest fixes source,
tree, complete fixture, canonical-universe and answer hashes, node/compiler
revision, mainnet activation, publication/provenance and existing baseline hashes.
The integration test additionally fixes the manifest and answer digests, so
editing both a fixture and its manifest hash cannot silently change the inventory.

The answer key was authored from the synthetic code and finite universes before
legacy measurement, independently of mapper output. This is reproducible fixture
authorship, not separate human adjudication or an inventory of deployed protocols.
`truth`, selectors, guards, true/false tuples, permitted premises, action vectors
and unsupported reasons are expected facts for future gates; they are not proof
artifacts. Discovery tuples describe identity observations even in optional or
negated code. They confer no necessity. Lexical site anchors are explicitly not
checked correspondence to typed tree nodes; M03 must establish that independently.

Each universe is constructed through the existing strict `WireBox` API and
recompiled from exact source. Test-only scenario adapters supply the listed
inputs, data inputs, outputs, registers and input-local extensions to the pinned
engine. Successful reduction is not a full node-accepted transaction or a
universal proof. The four mandatory canonical omission families remain requirements
of M03/M05, not counted as delivered by M00. All 18 unsupported/adversarial members
remain present, including the positive supplied-index and AVL examples whose
static relation reasoning is unsupported. These members still execute concrete
engine vectors. Unsupported does not mean an engine failure or a dropped case.

The vectors exercise distinct companion versus SELF, guarded alternatives,
data/output-only identity, negated checks, different exact script constants,
nonzero token slots and fungible duplicates, tokenless identities, existential
searches, supplied computed indices, fixed versus mutable config registers,
hash checks versus mandatory extension execution, input-local variable scope,
real AVL lookup proofs, and capped coincidental discovery. In particular the
optional extension control passes with a hash-matched serialized false expression;
the mandatory branch fails with those same bytes. The mutable-register control
accepts a different config/companion combination without changing A's code.

## Measured legacy output

[legacy-results.json](../../ergo-sandbox/tests/fixtures/mapping/legacy-results.json)
is reproduced exactly through the existing `map` and `tree_refs` APIs on every
run. It includes revision/input hashes, full canonical legacy map JSON payloads, caps and
truncations, explicit unresolved site dispositions, case/family member lists,
and the separately labelled public regressions. The test checks equality to the
saved results and prints artifact paths and hashes for the unchanged roadmap
runner to capture. It also authenticates the protected policy and old baselines.
There is no test-mode rewrite switch.

| Measurement | Actual result | Meaning |
|---|---:|---|
| Fixture accounting | 32/32 | Harness coverage, not “100% mapped” |
| Legacy literal slot observations | 35/52 sites | 17 sites have no corresponding legacy slot; all retained |
| Closed-fixture box reachability | 4/31 | Exact member IDs, excluding the seed |
| Reachability on M02-supported cases | 4/23 | Same inventory; unsupported-case totals remain above |
| Tuples in the registered dynamic families | 0/15 | Family-level projection onto expected discovery box tuples; case-level lists preserve the split |
| False proposal rate | `null` | 21 emitted edges, all 21 unadjudicated; zero adjudicated false edges is not a zero rate |
| Promoted false relations | 0/0, rate `null` | Legacy has no checked-relation producer |
| Necessity, action accuracy, omission refutation | `null` | No corresponding legacy producer |
| Deployed-protocol completeness | `null` | No known complete deployed denominator |

The legacy projection above does not measure recovery of extension execution or
AVL credentials as box edges. Those unsupported relation classes remain in the
answer key and have no legacy recovery claim. Results contain per-case dynamic
and reachability member lists and support labels, preserving family/support splits.

The existing USE fixture reproduces 26 nodes / 106 edges / 8 findings; DexyGold
reproduces 26 / 107 / 8. Both retain their recorded token-query truncations and
unknown protocol-completeness denominators. Neither contributes to the 32-case
synthetic denominator. No existing metric, corpus, cap, verdict, P-unit flag,
threshold, stop resolution or baseline revision is modified.

## Pre-registration correction

Before marking M00 implemented, the first test run caught a draft input defect:
the nonzero-slot omission used a tokenless U, which raised an index error instead
of reaching the authored false comparison. The final draft gives U two unrelated
tokens in that pair, preserving the original expected answer bytes, case membership,
and intended distinction. All 67 outcomes were then checked before finalizing the
manifest lock. The [failed run](pre-registration/inventory-failure.log),
[draft manifest](pre-registration/draft-manifest.json) and two original draft
fixtures are retained as authoring history, outside the registered inventory.
They are not an earlier accepted baseline. No design gate was amended or weakened.

The first workspace run also caught a serialization collision with the frozen
decompiler corpus: that gate recursively discovers `tree` and `ergoTree` JSON
fields. New mapping fixtures therefore use `treeHex` and `propositionHex`, with
conversion confined to the test adapter. Legacy output is retained verbatim as
`legacyMapJson` strings. This representation change preserves all exact source,
tree and canonical box bytes, answer facts and metric counts, while keeping the
new inventory separate from the old 339-entry decompiler denominator. The
[failed workspace run](pre-registration/workspace-corpus-collision.log) is retained;
no old test or expectation file was edited.
