# M02 — bounded supplied-material discovery

Implemented on `mapping/m00-m05`, based on
`ca38fd4508a3144345e38c5301fcb5bf0dcc4443`, left uncommitted for author review.
The author's implementation request authorizes M02 following PR #97; the design
record's proposal-only status is historical. This unit retains the registered
three-day ceiling, dependency M01, package `ergo-sandbox`, target
`mapping_discovery`, and all three original required test names. M03–M05 are not
implemented.

`map::discover_refs::discover` reads one supplied root using the existing pinned
parser and lift. It observes literal box IDs, proposition bytes/hashes, token IDs
at literal positions, and input existential identities, including nested token
existentials. Scoped lifted aliases are followed within a bounded walk. Matching
uses only supplied canonical boxes, validated through `WireBox::from_record`.
Tokenless boxes need no invented token. Token identities may match multiple
boxes; an emitted token selector's amount describes the observed target, not an
amount constraint inferred from an ID-only equality. This is identity-reference
discovery, not evaluation of an entire existential predicate or its guard.

The output contains the existing `discovery-map:v2` envelope plus separately
accounted lexical inventory sites. Optional and negated checks, data inputs and
outputs may yield identity observations. Untyped register constants may yield
explicit token-collision hints. Neither observation, import nor nomination
establishes a relation, an action set, transaction acceptance or necessity.
M01's artifact implementation and fixtures are unchanged.

All 52 registered source sites receive explicit unresolved dispositions: M00
registered lexical spans, and the existing lift does not provide exact source
correspondence. Recovered identities are separately anchored by lift-local IDs.
The site-accounting figure measures accountable disposition, not successful
source-to-tree alignment. Computed indices and AVL sites explicitly name their
unsupported class; they produce no guessed targets. Register-derived identities,
context execution and arbitrary dispatch remain unresolved where no independent
literal identity can be observed. This unit adds no exact-tree proof checker.

Caps on root bytes, lifted nodes, supplied boxes and comparisons are disclosed in
every map. These are parameters of the new finite-material API, not changes to
legacy map/drain caps. Exhaustion prevents a partial scan from counting as
observed recovery. Malformed canonical material, duplicate IDs, explicit source
inconsistencies and missing/mismatched subject bytes prevent observed recovery.
Missing pages, unsupported queries, unknown inventory totals and unknown snapshot
premises remain explicit reasons; already supplied literal matches do not certify
query completeness. Snapshot and raw-record provenance remain supplier assertions,
not independently verified simultaneous unspentness. No fetching, historical
state service, detector, search axis, drain, objective or UI change is included.

The gates load and hash-check the pinned manifest, independent answers and every
case. They exercise the real discovery API on all 32 cases and compare the entire
result to [m02-mapping-results.json](m02-mapping-results.json), including member IDs,
revision/input hashes, raw records, queries, caps and unresolved reasons. Additional
in-memory controls test script hashes, aliases, budget boundaries, invalid claimed
box IDs, duplicate and inconsistent responses, missing pages, unsupported queries,
unknown snapshots and parse failures. They do not edit registered cases or answers.
