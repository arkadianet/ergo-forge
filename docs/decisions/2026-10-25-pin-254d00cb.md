# Governing decision: node pin 55229e00 → 254d00cb — 2026-10-25 UTC

The founder authorizes moving forge's engine pin from `55229e0040b83b57521334030fe2842e85d43422`
(node 0.13.1) to `254d00cbeb8070d3804d363862aa157ad1c6cb15` (node main after 0.13.1: #669/#670
ErgoTree header fix, #672 walletd, #673/#674 CSE fix), and the baseline updates below. This is the
"versioned governing decision" the mapping and property pins ask for.

## What changes

- **Pin.** The node declarations in `Cargo.toml` and `ergo-sandbox/Cargo.toml`, one `Cargo.lock`
  re-resolution (reviewed SHA-256 in `docs/reports/node-pin-254d00cb/Cargo.lock.sha256`), and the
  engine revision in `node_validation.rs` and `node_corpus_expectations.json`. Needs rustc 1.99.0.
- **#670: the compiler writes the requested tree version into the header** (Scala parity). Forge keeps
  its rule: an unflagged compile gives a v0 header unless a v6 method or v6-only constant data needs
  the requested version (3). Sources with v6-only data, such as `UnsignedBigInt`, now compile at the
  default and get a v3 header, where the earlier pin refused them. An explicit `--tree-version N`
  still writes exactly vN. The change is in `ergo-sandbox/src/compile.rs`
  (`stamp_version`, `with_v0_header`, `compile_source_raw`).
- **`compile.rs` hash.** `ergo-sandbox/src/compile.rs` changes, so its hash in
  `fixtures/properties/manifest.json` changes with it.
- **#673 (IsProven cancel after CSE) changes compiled trees of bundled examples.** Three round-trip
  outcomes move: `chaincash-basis/chaincash/onchain/receipt.es` (now byte-identical),
  `curve-trees/CurveTreeVerifier-v6.es` (now compiles; its round trip fails to recompile) and
  `lsp/zed-extension-test.es` (still recompiles-but-differs, new tree). `decompile_corpus_expectations.json`
  is a frozen roadmap baseline and stays byte-identical; `decompile_corpus.rs` corrects the three rows
  from the measured outcome, as the 55229e00 bump did for the typer rejections. The deployed-corpus
  sweep keeps its recorded rows; `mutation_corpus.rs` exempts these sources from the tree-hash and IR-id
  comparison (and `CurveTreeVerifier-v6.es` from its recorded refusal).
- **Pinned digest that follows.** Only `ergo-sandbox/src/compile.rs` changes among the hashed
  baselines, so its entry in `fixtures/properties/manifest.json` changes, with `MANIFEST_SHA` in
  `property_support/mod.rs` and the properties recorded results that carry that manifest hash. The
  mapping manifest and its results are untouched. No expected verdict, count or answer changes.
- **Test harness.** `ergo-web/tests/evidence_replay.rs` asks `node --test` for the TAP reporter,
  which newer node no longer picks outside a terminal.
