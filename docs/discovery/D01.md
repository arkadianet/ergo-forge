# D01 — strict author declarations

D01 implements the two-person-day schema unit authorized after PR #99 on
`discovery/d00-d04`, based on committed D00
`1d038ec6796b3b37b85205471c86b69f559b7743`. Changes are uncommitted for author
review. Only D01 is added to `roadmap-policy:v1`, with the exact proposed D00
dependency, two days, `ergo-sandbox` package, `property_schema` target and three
test names. D02–D04 remain unregistered and unimplemented. Capability 1 can
remain the endpoint; the existing cancellation of capabilities 2 and 3 stands.

The opt-in `properties::schema::Declaration::parse` entry point validates finite
`author-property:v1` inputs. It rejects missing/unknown fields, duplicate keys,
unknown versions/operators, incompatible units, undeclared roles/registers and
ambiguous scalar bindings. The normalized declaration has private fields and
shared-reference getters, no deserializer, and a SHA-256 identity over every
normalized input field. `DeclarationInput` is a round-trippable input DTO;
constructing or deserializing that DTO grants no checked-declaration authority.
Hex is normalized to lowercase, decimal i128 literals to canonical decimal,
and named maps to key order. Input arrays retain order. No caller-supplied
identity or verdict is accepted.

The schema supports Boolean connectives, exact byte equality, integer comparisons,
counts, ERG/token sums, named typed R4–R9 integer registers, height, addition,
subtraction and multiplication by a literal. Integer literal strings retain the
entire signed i128 domain without JSON number rounding. Units distinguish
nanoERG, each exact token ID, count, height, scalar and named accounting amounts.
Arithmetic requires identical units; literal scaling preserves the operand unit.
Checked runtime arithmetic and missing/wrong-type register observations belong
to D02, which has not been started. Successful schema checking does not assert
that an expression will execute without overflow.

The fixed limits are 32 total expression nodes across guard and assertion,
eight roles, 16 boxes per collection, eight token entries per inspected box and
eight transactions per supplied trace. Both collection and trace shape checks
are input checks only. Future replay must enforce them on actual parsed material.
The bounded-response scope records horizon 1–4 and the source/digest of the
supplied schedule; guard means trigger and assertion means successor goal on one
trace. The reference is not a checked schedule. Alternative-trace comparison,
unbounded eventuality, dynamic code and variable multiplication are refused.

`bind_roles` inspects existing canonical `WireBox` inputs and returns explicit
positions only. It never calls a validator or evaluator. Exact positions, IDs,
scripts and token-ID predicates are collection-specific. Missing or ambiguous
`exactly-one` bindings return `unresolved`; `all-matches` can be empty, without
inventing existence, uniqueness, signer identity or successor inheritance.
Actual empty sums, property truth and accepted trace observations await D02.
The guard and assertion are declarations, not evaluated here.

There is no result type, replay envelope, violation producer, reachability
promotion, evaluator or contract-defect adjudication in D01. A faithfully
refutable author assertion can itself be mistaken. `holds-on-execution` will
never mean proved or safe, and only a future non-deserializable result built
from fresh accepted execution may carry `violated`. The existing evidence APIs,
CLI/HTTP/UI, extraction property and all frozen corpus data remain unchanged.

The M00 authentication function first compares the complete policy to the exact
original snapshot plus authorized D00 resolution/registration and D01
registration, then checks the original projection against the unchanged anchor
`41729240759244bd3edc833e31359bfe50d8430f0b5a2e27ebc727706363cd10`.
D00 is now pinned implemented. Only D01's own flag/completed-prefix pair can
vary between its pre-completion and completion states. Recursive mutations of
all fields, structural removals/insertions/duplicates/reordering, coherent D00
rollback and D02/D03/D04 appends must fail the real checker.

No design amendment or threshold change was needed. During development, an
adversarial unknown-field test exposed Serde's permissive handling of tagged
unit variants. Empty struct variants fixed it without changing the gate; the
same recursive regression now passes. An initial required-prefix run keeps D01
unimplemented deliberately until direct schema and predecessor gates have run;
its unimplemented status is scheduling evidence, not a measured product stop.
