# D02 — fresh property evaluation and supplied trace checking

D02 implements the author-authorized three-person-day unit after PR #99, on
`discovery/d00-d04` at committed D01 `1291e53902243fa02820709c65d836a002703c72`.
The changes are uncommitted for author review. The registration retains exactly
the proposed D01 dependency, three days, `ergo-sandbox` package,
`property_evaluation` target and four test names. D03 and D04 remain unregistered
and unimplemented. Capability 1 may remain the endpoint; this change plans no
capability 2 or 3 work.

`properties::evaluate::evaluate` accepts a checked D01 declaration and a
`SuppliedTrace`. It calls `evidence::validate::validate` freshly for every
supplied step, including the nominated trigger at index zero. It evaluates only
observations from those accepted canonical transactions. `Evaluation` has a
private field, shared inspection only, and no deserializer; compile-fail tests
reject constructing or importing it. Inspection JSON is not claim authority.
Execution or linkage rejection returns an error separately from property status.
No old replay envelope, claim vocabulary, validator, CLI, HTTP or UI changes.

The checker starts with explicitly registered canonical root boxes, rejects
unexplained or spent snapshot members, resolves input and data-input references
against the live set, removes consumed boxes, and adds outputs materialized by
the existing canonical wire API. It rejects reused output identities. Every step
still requires the node's acceptance against its own supplied snapshot, including
its data inputs. This is orchestration and UTXO bookkeeping, not a second
transition interpreter, initialization builder, action constructor or proposer.

The schedule is an ordered vector of `schedule_step(request)` objects: exact
transaction bytes, protocol parameters, network rules, block context, headers,
local policy and prior block cost, including their supplied provenance. No extra
or missing schedule fields are accepted. Bounded response additionally checks
its declaration's schedule SHA-256 against `digest(schedule)`. This digest uses
Serde's compact JSON serialization with ordered object keys. Heights and
timestamps cannot decrease. At equal heights, environmental premises must agree
and prior cost must equal the preceding fresh node result's total block cost.
At a later scheduled height the explicit prior cost is an external premise;
there is no claim about intervening chain history or future inclusion. Qualitative
fairness or eventuality is not expressible as this exact finite schedule.

For transition scope exactly one transaction is required. For response scope,
step zero is the supplied trigger; the assertion is the goal on each of its K
successors, for K=1..4. These are observations from one trace, with index and
canonical prefix digest, never comparisons between alternative traces. A missing
horizon is unresolved even if an early goal appeared. A true trigger and complete
accepted horizon with all goals false yields `violated`; a completed horizon with
a goal yields `holds-on-execution`. False guard yields `not-applicable`, and
missing bindings, missing or mistyped registers and arithmetic overflow remain
`unresolved`. No declared contract in a step's observed collections also leaves
scope unresolved. All roles are rebound for each step through unchanged D01
binding checks. No implicit successor binding or signer identity is introduced.

Checked i128 arithmetic implements the complete D01 expression fragment,
including empty all-matches sums of zero, counts, token quantities, integer
registers, bytes and heights. D01 retains the 32-node, eight-role, 16-box,
eight-token and eight-transaction ceilings without modification. Each evaluated
operand includes its expression (and thus its declared unit). Reports include
bindings and exact box IDs, guard and successor outcomes, first failing
assertion/index, node execution reports, declaration/root/schedule/request/prefix
and combined premise identities, and evaluator/node revisions.

A faithfully refuted author assertion is not automatically a contract defect:
`modelReview` and `contractDefect` remain separately `not-adjudicated`.
Reachability remains `assumed-root`, even after every step passes. This neither
establishes a universal property nor certifies safety, historical occurrence or
reachability from a validated initialization. D03's full inventory agreement,
replay envelope and semantic usefulness measurement are not claimed here.

The four registered tests exercise supplied witness/control pairs for all four
families with independent concrete operand expectations, unknown/empty/type/
overflow cases, complete horizons K=1..4, missing horizons, reversed schedules,
reused spends that individually pass the node, missing roots and data inputs,
tampered schedule/transaction bytes, the unchanged trace ceiling, same-block
cost accumulation/reset rejection and genuine node rejection. Additional
canonical successors and data-input requests exist only in the test harness;
the pinned D00 fixtures and expected answers are never rewritten.

Policy authentication compares the complete original snapshot plus exactly the
D00 resolution and D00/D01/D02 registrations before projecting to M00's unchanged
anchor `41729240759244bd3edc833e31359bfe50d8430f0b5a2e27ebc727706363cd10`.
D00 and D01 remain pinned implemented. Only D02's own implementation/completed
prefix pair varies. Earlier recursive field and structural rejection probes are
retained, including duplicate/later-unit additions, protected-field changes,
D00 rollback, and a new explicit coherent D01 rollback rejection.

No design amendment, raised ceiling, changed expected fact or stop record was
needed. Initial test development caught an incorrect new control expectation
and an invalid new same-block context (outputs from a future height). Both were
corrected in the new tests; the node rejection and all pinned data stayed intact.
D02 supplies the linked checker required by the review correction; it does not
claim that D03's later semantic or usefulness gate will pass.
